# Android WebDAV 备份与恢复开发计划

本文记录 Android 端 WebDAV 备份与恢复的后续开发方向。当前实现先保证单次手动备份和恢复可用，后续再补充历史版本、稳定传输和自动化能力。

## 当前版本

当前实现位于 [`DataTransferManager`](../../clients/android/app/src/main/kotlin/dev/clawseed/demo/datatransfer/DataTransferManager.kt)、[`WebDavSyncClient`](../../clients/android/app/src/main/kotlin/dev/clawseed/demo/datatransfer/WebDavSyncClient.kt) 和 [`DataTransferSection`](../../clients/android/app/src/main/kotlin/dev/clawseed/demo/ui/settings/DataTransferSection.kt)。

已支持：

- 在导出区域选择本地文件或 WebDAV；
- 在导入区域选择本地文件或 WebDAV；
- 复用现有分类选择、敏感数据过滤和导入策略；
- 远端配置只保存文件夹，例如 `OneDrive/clawseed`；
- 文件名由应用自动生成，例如 `clawseed-20261020-config.zip`；
- 使用 AES-GCM 加密备份内容，WebDAV 服务端不会收到备份加密密码；
- 使用 Android Keystore 加密保存可选的 WebDAV 登录密码；
- 备份成功后记录最近一次远端文件，并自动准备对应的导入分类；
- 使用 WebDAV `PROPFIND` 列出远端文件夹中的历史备份，并支持选择任意文件恢复；
- 在远端备份列表中删除应用生成的历史备份，删除前需要确认；
- WebDAV 备份和恢复使用应用缓存文件与流式加密传输，避免把完整压缩包保存在内存中；
- 兼容旧版本保存的远端文件路径。

当前限制：

- 没有自动定时备份和远端保留策略；
- 备份加密密码默认不持久化，重新打开应用后需要再次输入；
- 不同 WebDAV 服务的认证、目录创建和错误响应还没有统一诊断界面；
- 暂未实现断点续传和网络恢复后的自动重试。

## 第一阶段：远端备份列表与历史恢复（已完成基础版）

目标是让用户能够查看文件夹中的多个备份，并选择任意一个恢复。当前版本已经完成基础实现：客户端通过 `PROPFIND` 获取列表，导入区域展示文件名、大小和修改时间，并默认选中最近一次记录的文件。

实现内容：

1. 使用 WebDAV `PROPFIND` 获取远端文件列表；
2. 只展示应用生成的备份文件，过滤临时文件和未知格式；
3. 从文件名解析日期和分类，显示文件大小与修改时间；
4. 将最近备份作为默认选项，同时允许用户选择历史文件；
5. 恢复前显示选中的备份信息和将要导入的分类。

验收标准：

- 能列出配置文件夹中的多个备份；
- 上传中断留下的临时文件不会出现在可恢复列表中；
- 选择历史文件后可以按现有导入策略恢复；
- 列表为空、认证失败和服务端不支持 `PROPFIND` 时都有明确提示。

## 第二阶段：大文件与弱网络传输

目标是降低大备份的内存占用，并让移动网络切换或短暂断网后更容易恢复。

实现内容：

1. 使用应用缓存目录中的临时文件生成 ZIP 和加密内容（已完成）；
2. 上传和下载改为流式处理，避免同时保留完整明文和密文数组（已完成）；
3. 为连接、读取、写入分别设置可配置超时（已完成基础配置）；
4. 对幂等上传增加有限重试，继续使用临时文件加 `MOVE` 提交；
5. 网络恢复后允许用户手动重试，必要时再增加断点续传；
6. 明确区分认证失败、目录创建失败、空间不足、超时和密码错误。

验收标准：

- 备份大小接近限制时应用不会因为内存峰值崩溃；
- 上传失败不会覆盖上一次成功备份；
- 网络短暂中断后重试可以完成上传或恢复；
- 错误信息能指出失败阶段和 HTTP 状态码。

## 第三阶段：加密密钥与恢复安全

目标是让加密备份更容易使用，同时避免用户误覆盖现有数据。

实现内容：

1. 增加加密密码确认和强度提示；
2. 支持用户保存一个本地密钥别名，密码正文仍由 Keystore 保护；
3. 恢复前展示备份时间、分类和目标数据范围；
4. 对配置、会话、记忆、技能和用户画像分别显示覆盖风险；
5. 恢复失败时保留原数据，不清理未完成的导入临时文件；
6. 校验备份格式版本，保留未来格式迁移入口。

验收标准：

- 密码过短、确认不一致和密码错误都有可理解的提示；
- 解密失败不会修改任何目标数据；
- 用户确认前不会执行覆盖型导入；
- 旧格式备份可以明确提示兼容性，而不是显示笼统的网络错误。

## 第四阶段：自动备份与远端保留策略

目标是支持不打开设置页面也能按计划备份。

实现内容：

1. 增加每天、每周和仅 Wi-Fi 等计划选项；
2. 复用 Android `ClawseedService` 执行备份，使用 Foreground Service 处理长任务；
3. 保存任务状态、最近成功时间、失败原因和重试次数；
4. 支持保留最近 N 个备份；
5. 清理前先确认文件属于当前应用生成的备份；
6. 设备重启、应用更新和时区变化后重新注册任务。

验收标准：

- 同一个计划触发不会重复上传；
- 设备重启后计划仍然有效；
- 自动备份失败会通知用户，但不会删除最近一次成功备份；
- 保留策略只删除明确属于应用的旧备份。

## 第五阶段：服务兼容性与诊断

目标是减少 Koofr、Nextcloud、坚果云等服务之间的行为差异。

实现内容：

1. 增加“测试连接”按钮，分别验证 URL、认证、目录访问和写权限；
2. 对 `MKCOL` 返回 `405`、`409` 等常见响应做服务端兼容处理；
3. 记录请求阶段、状态码和可安全展示的错误信息，不记录密码和备份明文；
4. 为常见服务提供配置示例和路径说明；
5. 增加 WebDAV 加密、路径规范化、旧配置迁移和恢复流程测试。

验收标准：

- 用户可以在真正上传前确认配置可用；
- 认证失败能区分用户名、密码或应用专用密码问题；
- 日志不包含 WebDAV 密码、加密密码或备份内容；
- 常见 WebDAV 服务完成至少一次上传、列表和恢复验证。

## 推荐交付顺序

1. 远端备份列表与历史恢复；
2. 临时文件和流式传输；
3. 加密密码确认、恢复预览和格式版本；
4. 测试连接与服务兼容性诊断；
5. 自动备份和远端保留策略。

自动备份放在后面，是因为它依赖稳定的传输、清晰的错误状态和可选择的历史文件；在这些基础能力完成前，自动任务容易产生重复备份或无法恢复的失败状态。
